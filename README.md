# FS Config

Самостоятельный Android-конфигуратор приборов с подготовкой к USB OTG/RS-485 и Wi-Fi.

## MVP-каркас

- Kotlin + Jetpack Compose / Material 3 с русским интерфейсом.
- `core:model`: типизированные приборы, конфигурации, поля и журнал обмена.
- `core:transport`: единый API транспорта, simulator и безопасный блокировщик неподтверждённого протокола.
- `app`: самостоятельный русский Compose UI с отдельными экранами подключения, конфигурации, журнала и файлов.
- Состояния интерфейса: загрузка, ошибка операции, пустое состояние и заблокированное реальное подключение.
- SAF: открытие и сохранение версионированной JSON-конфигурации через системный выбор файлов.
- Тест: round-trip JSON сохраняет типы полей и неизвестные расширения.
- CNU codec: текстовый контейнер с упорядоченным заголовком, raw-строками `LineN`,
  сохранением неизвестных ключей/исходных строк и проверкой счётчиков/диапазона 0..255.
- Редактор конфигурации содержит собственные адаптивные зоны параметров, выбор адреса,
  разделы зон/прибора/выходов/клапанов/доступа/ключей, диапазоны bulk-операций и
  маскированный placeholder ключей. Семантика и операции записи активируются только
  после официальной карты полей.
- Подключение разделяет профили USB Serial/RS-485 (baud, data bits, parity, stop bits,
  flow control, адрес) и Config по Wi-Fi (TCP/IP host, port, timeout, keep-alive). Профили можно
  сохранять в текущей сессии и проверять на валидность/доступность simulator-канала.
  TCP-проверка не является подтверждением конкретного протокола: framing и команды заблокированы
  до получения официальной спецификации.

## Протокол

Реальные команды, CRC, адресация, параметры RS-485 и Wi-Fi endpoint не угадываются и не извлекаются из InstallUProg.exe. Для совместимости нужна официальная спецификация/SDK производителя либо разрешённые тестовые дампы. До этого simulator позволяет разрабатывать UI и хранение без риска записи неверных данных.

Файл CNU разбирается только как наблюдаемый текстовый контейнер: приложение показывает
метаданные и raw-конфигурацию, но не приписывает отдельным байтам смысл. Неоднозначные
`LineCount`/`LengthConfiguration` сохраняются и выдаются как предупреждения. Редактирование
байтов и запись CNU в прибор намеренно не реализованы; пользовательский sample-файл в
репозиторий не добавляется.

## Сборка и статическая проверка

Откройте проект в Android Studio с Android SDK 35 и выполните:

```powershell
.\gradlew.bat assembleDebug
```

В текущем репозитории Gradle Wrapper пока не добавлен. Если `gradlew.bat` отсутствует,
импортируйте проект в Android Studio с установленным Gradle/Android Gradle Plugin и
запустите `app > Tasks > build > assembleDebug`. Минимальная версия Android — API 26.

## GitHub Actions и APK

Workflow `.github/workflows/android-apk.yml` запускается после push в `main` или `master`
и вручную через `workflow_dispatch`. Первый push после добавления workflow запускает
сборку. Gradle 8.9 устанавливается через `gradle/actions/setup-gradle@v4`; если в
репозитории появится полноценный Wrapper, workflow автоматически предпочитёт его,
иначе использует установленный Gradle 8.9. После успешной сборки APK доступен в GitHub
Actions в разделе **Artifacts** под именем `fs-config-debug-apk`.

Скачайте artifact со страницы завершённого workflow run, распакуйте архив и установите
`app-debug.apk` на тестовое устройство. Это debug APK: он не предназначен для production,
не заменяет release-подпись и не должен публиковаться как готовый production-релиз.

Без Gradle можно выполнить доступные проверки:

```powershell
git diff --check
Get-ChildItem -Recurse -Filter *.xml | % { [xml](Get-Content -Raw $_.FullName) }
```

Эти проверки ловят ошибки whitespace и некорректный XML, но не заменяют Kotlin/Android
компиляцию. Реальный транспорт намеренно не активируется без официальной спецификации.
